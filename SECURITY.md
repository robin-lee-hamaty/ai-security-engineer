# Security Policy

## Educational purpose

This repository is an **educational resource**. It teaches defensive AI security through explanation, defensive demonstrations, and safe laboratory exercises. Any offensive technique is presented so that it can be understood, detected, and defended against.

Security examples and laboratory techniques must only be executed against systems and environments that you **own** or are **explicitly authorized** to test. Prefer synthetic data and isolated environments. Never test against production systems or third-party systems without written authorization.

## Reporting an issue

Because this is a book and knowledge base rather than a running service, "security issues" here mean problems that could make a reader's learning unsafe or incorrect, for example:

- an example that could cause harm if a reader ran it outside an isolated lab;
- a lab exercise that fails to contain its blast radius as described;
- guidance that is factually wrong in a way that affects safety.

To report one, open a GitHub issue describing the problem and where it appears (section or page). For a sensitive report, you may instead contact the author privately through the repository profile.

## Please do NOT submit

- real secrets, credentials, API keys, tokens, or private data;
- evidence of unauthorized access to any system;
- malware or live exploit payloads;
- third-party copyrighted material.

Contributions containing any of the above will be rejected.
